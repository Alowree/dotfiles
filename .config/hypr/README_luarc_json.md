## What Is `~/.config/hypr/.luarc.json`?

This is a **Lua Language Server configuration file** for **Lua Language Server** (lua-language-server), which is a popular LSP (Language Server Protocol) implementation for Lua.

When you're writing **Hyprland configuration in Lua** (which is becoming more common), this file helps your editor (VS Code, Neovim, etc.) provide:

- **Autocompletion** for Hyprland-specific functions and variables
- **Syntax highlighting** for Hyprland APIs
- **Go-to-definition** for Hyprland functions
- **Error detection** (like typo in Hyprland function names)

## What the File Does

### 1. `"workspace": { "library": ["/usr/share/hypr/stubs"] }`

This tells the Lua LSP to load **type definition files** (stubs) from that directory.

**What are "stubs"?**

- Files that describe the Hyprland API to the LSP
- They don't contain actual code, just **function signatures, parameter types, and return values**
- Like a `.h` header file in C or a `.d.ts` file in TypeScript

**Without this:** Your editor won't know about Hyprland-specific functions like `hypr.set_layout()`, `hypr.get_workspace()`, etc.

**With this:** Your editor understands Hyprland's API and provides intelligent autocomplete.

### 2. `"diagnostics": { "globals": ["hl"] }`

This tells the LSP that `hl` is a **known global variable** and **not to report it as undefined**.

In Hyprland Lua configs, `hl` is often used as shorthand for the Hyprland API object (e.g., `hl.workspace.create()`). Without this line, the LSP would show a warning like:

```
Undefined global 'hl' [undefined-global]
```

## `/usr/share/hypr/stubs` vs `/home/username/.config/hypr`

### The Difference

| Path                          | What it is                                              | Use Case                                                |
| ----------------------------- | ------------------------------------------------------- | ------------------------------------------------------- |
| `/usr/share/hypr/stubs`       | **System-wide** stubs installed by the Hyprland package | Works for all users, maintained by your package manager |
| `/home/username/.config/hypr` | **User's personal** config directory                    | Where you put your own Lua scripts and **custom stubs** |

### Why Some YouTubers Use `~/.config/hypr`

Two reasons:

1. **Historical/Outdated Content**: Older videos might show this because:
   - [ ] The stubs directory location changed during development
   - [x] They manually downloaded or generated stubs into their config directory
   - [ ] They're using an older version of Hyprland

2. **Custom Stubs**: If you create your **own Lua modules** or have **custom wrapper functions**, you'd want to point the LSP to your config directory to load those custom definitions:

```json
{
  "workspace": {
    "library": [
      "/usr/share/hypr/stubs", // Official Hyprland API
      "/home/username/.config/hypr" // Your custom Lua modules
    ]
  }
}
```

## Which One Should You Use?

**Use the system path** (`/usr/share/hypr/stubs`) because:

- ✅ It's maintained by your package manager (`pacman` updates it)
- ✅ It's the official location for Hyprland API stubs
- ✅ Works out of the box with no extra setup

**Only add your config directory if**:

- You have custom Lua modules in `~/.config/hypr/`
- You're writing a helper library that other Lua files import
- You want the LSP to understand your own functions

## Bonus: How to Verify

Check if your stubs exist:

```bash
ls -la /usr/share/hypr/stubs/
```

You should see `.lua` stub files for Hyprland's API. If they're there, your LSP config is correct.
